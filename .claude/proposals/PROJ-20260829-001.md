## 问题/机会

Dashboard v1 只有"总览 + 审批中心"两个页面,实际使用暴露三个痛点:

1. **工单详情入口太深**:工单详情页虽存在,但只有审批中心内有链接;总览"今日事件摘要"里工单号是纯文本,查看具体工单只能手敲 `http://127.0.0.1:8321/ticket/T-2026-0828-003` 这种 URL。
2. **缺全量工单视图**:没有地方能浏览/检索所有工单,只能碰运气在审批中心或事件摘要里找。
3. **缺跨项目视角**:ai-factory、sk-video-studio、datahub-demo 多项目并行,总览只有"运行中 N"这类聚合数字,看不出哪个项目卡在哪个阶段。

机会:`Ticket` 模型自带 `project` 字段,泳道图不需要动数据层,纯展示层工作。

## 建议方向

Dashboard v2,三个增量(已与提出人对齐):

1. **工单中心**(新导航页):全量工单列表 + 项目筛选 + 状态筛选 + 关键词搜索 + 排序,每行点击进详情。
2. **项目中心**(新导航页):泳道图,行=项目、列=阶段(P0 提案→P5 发布+挂起),格内放工单 chip(工单号+摘要),点击进详情;一眼看出各项目堵在哪。
3. **总览最小改动**:事件摘要工单号变链接、待审批卡片可点击跳审批中心、新增一行"各项目状态迷你条"(每项目一格,显示运行中/待审批/挂起计数,点击跳项目中心)。

## 粗略范围

- `orchestrator/dashboard/`:新增 2 个路由 + 2 个模板,改 `base.html` 导航、`index.html`、`views.py` 装配函数。
- 筛选/搜索/排序优先服务端实现(GET query 参数),不引入前端框架。
- 配套单测(`tests/orchestrator/test_dashboard.py` 扩展)。

## 不做什么

- 不改 Ticket 数据模型、不动状态机/台账/事件层。
- 不做甘特/时间轴形态(无时间字段,成本高,已否决)。
- 不重做总览首屏为项目健康视图(保留现有指标卡布局)。
- 不引入 JS 框架/构建链;不做权限、多用户。
