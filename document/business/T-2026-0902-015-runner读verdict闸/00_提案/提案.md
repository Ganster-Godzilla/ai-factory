# 提案:runner 推进读 QA verdict(不只认退出码)

- 工单:`pool/tickets/T-2026-0902-015.yaml`
- 类型:feature / 平台改进(编排器 runner)
- 优先级:normal
- 关联规则:R11(`.claude/rules-registry.md`)
- 溯源事故:T-2026-0902-010(QA 写"不通过/D1 P0"仍被推进 p5)

## 问题

runner 推进 `p4_verifying → p5_ready` 的唯一依据是 `role_run.status == "done"`
(`orchestrator/daemon/runner.py:405`),即 **agent 进程退出码**。它**不读 QA 验收报告
里的结论**。于是:

- T-2026-0902-010 的 QA 报告白纸黑字写"**不通过**,D1 为本单引入的 P0",
  但 agent 干净退出(exit 0),runner 照样把工单推进到 `p5_ready`,
  带病的 D1(pytest 收集撞名 P0)被一路递到 release,合并前全量测试才炸。
- 质量闸形同虚设:**它回答的是"程序跑完没",不是"事做对没"**。

## 方向

qa(及审核类角色)推进前,runner 必须从其产物中解析出**显式判定**,
只有"通过/GO"才允许 `transition`;其余(不通过/NO-GO/缺判定)→ 挂起退回。

- verdict 解析落 `orchestrator/daemon/gates.py`(与现有产物门禁同层),
  判定来源:QA 验收报告的"结论"章节(锚定该页独有标题,防导航栏空转断言,R6)。
- 报告缺"结论"章节或无法解析 → 按"不通过"保守处理(fail-closed),不静默放行。
- 判定结果写事件流(`verdict=pass/fail`),留痕可审计。

## 范围

`orchestrator/daemon/gates.py`(verdict 解析)+ `orchestrator/daemon/runner.py`
(p4→p5 推进前接 verdict 闸)+ 对应测试。验收标准:

1. 构造 QA 报告写"不通过"的工单,runner **不得**推进 p4→p5,转挂起并留 verdict=fail 事件。
2. 报告写"通过"且产物门禁过 → 正常推进,留 verdict=pass 事件。
3. 报告缺"结论"章节 → 按不通过处理(挂起),不静默放行。
4. 现有 p4→p5 正常路径(报告写通过)零回归,`pytest tests/` 全绿。

## 不做

- 不改 QA 角色提示词的报告模板结构(若需统一"结论"章节格式,另立单)。
- 不动其他状态推进边(仅 p4_verifying→p5_ready 加 verdict 闸)。
