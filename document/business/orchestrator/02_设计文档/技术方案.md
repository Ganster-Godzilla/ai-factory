# 技术方案: T-2026-0829-004 dsh 现金闸"明放"模式

> Phase 2 产物,依据 document/business/orchestrator/01_需求分析/PRD.md。门禁:templates/gate-checklists/phase2-gate.md
> 重要前提变更:integration 合 main 后发现 a7de5d1(降级 hotfix)已成悬孤提交——integration 分支被回卷到 9fb0fcc,降级代码不复存在。本单从硬契约基线自行实现"明放",反而更干净。

## Architecture(结构与边界)

```
orchestrator/adapters/base.py   # HarnessResult + estimated: bool = False
orchestrator/adapters/dsh.py    # 无 trailer 降级:按 returncode 推进 + 估算 cost + 文案修正
orchestrator/daemon/ledger.py   # append_ledger + estimated: bool = False(只增不改)
orchestrator/daemon/runner.py   # _record_cost 透传 estimated;双闸 mingfang 降级为 budget_warn
orchestrator/dashboard/views.py # overview_data + mingfang_overdue 标记
orchestrator/dashboard/templates/index.html  # 明放到期横幅
orchestrator.yaml               # budgets 三键:mingfang_mode / review_after / ds_est_call_cny
```

配置读取纪律:`(cfg.get("budgets") or {}).get(key, default)`,缺键安全兜底(与既有 `ds_daily_exceeded` 同款防御)。

## How(关键实现)

**1. 估算入账(F2/F3)**
- `DshAdapter.__init__` 增加 `est_call_cny: float = 0.0`;cli.py 建 adapter 时从 `cfg["budgets"]["ds_est_call_cny"]` 传入(缺省 0=不估,向后兼容)。
- 无 trailer 降级分支:`HarnessResult(status=按 returncode, usage_missing=True, tokens={}, cost_cny=self.est_call_cny, estimated=True)`。
- `USAGE_MISSING_MSG` 改为:`"dsh 未输出 usage trailer,本次按估算 ¥{est}/次 入账;真实用量待 T-2026-0829-002"`——删除"视同失败"语义;模块 docstring 同步。
- `_record_cost`:amount>0 时 `append_ledger(..., estimated=getattr(result, "estimated", False))`;ledger 条目含 `estimated` 键(布尔,新条目都写,旧条目无此键=精确值,消费方无需改)。

**2. 双闸 warn-only(F4/F5)**
- runner 新增 `_mingfang(cfg) -> bool`:`(cfg.get("budgets") or {}).get("mingfang_mode", False)`。
- 日现金闸(runner.py:116):超线时若 mingfang → `append_event(pool, ticket.id, "system", "budget_warn", gate="ds_daily", value=ds_day_cost, threshold=...)` 继续派发;否则维持 `"blocked: ds 日现金线"`。
- 工单预算帽(runner.py:118):超帽时若 mingfang → 同款 `budget_warn`(gate="ticket_cap")继续;否则维持 suspend budget_cap。
- 每次派发尝试超线都记事件(故意:重试烧钱的可见性正是明放的意义)。

**3. 复审提醒(F8)**
- `overview_data`:`mingfang = budgets.mingfang_mode`,`review_after` 解析为 date;`mingfang_overdue = mingfang and review_after and today > review_after`。
- index.html 顶部横幅:mingfang 中显示常驻提示条(模式+复审日),过期时变红色 `.error-banner` 样式。配置缺失→不显示。

**4. 配置(F6)**
- orchestrator.yaml budgets 段加:`mingfang_mode: true`(标注:磨合期明放,2026-08-29 boss 决策)、`review_after: "2026-09-12"`(双触发,另一触发=T-2026-0829-002 交付)、`ds_est_call_cny: 0.05`(DeepSeek 典型 dev 调用≈¥0.014,3 倍余量)。

**5. 杂项**:删除 merge 带入的 G7-commit-message.txt。

## 数据设计

- ledger.jsonl:条目新增 `estimated: bool`(只增不改,旧消费方 `_ds_month_cost`/`ds_day_cost` 按 resource+unit 过滤,不受影响)。
- 估算与精确值同列 `amount`——复审/T-002 落地后可按 `estimated` 拆分对账。
- 无其他持久化变更。

## Rollback(回滚方案)

- 运行态回滚:orchestrator.yaml `mingfang_mode: false` 即恢复硬闸(设计内开关,无需改码)。
- 代码回滚:纯增量(HarnessResult/append_ledger 都是可选参),git revert 单提交即可;ledger 已写条目不回溯(估算标记本就为事后对账)。
