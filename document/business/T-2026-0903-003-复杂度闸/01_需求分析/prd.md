# PRD:复杂度闸接入常设质量闸

- 工单:`pool/tickets/T-2026-0903-003.yaml`
- 阶段:P1 需求分析
- 类型:feature / 平台质量(常设闸)
- 溯源:2026-09-03 ruff/radon 扫描(用户二档);关联 002(拆分存量最烂函数)

## Why

ai-factory 无圈复杂度闸。2026-09-03 一扫即发现 `run_dev_tasks` 46(F 级)、`main` 25、
`check_gate` 24 等上帝函数——**函数在一次次改动中越变越胖,无人拦截**。002 已拆分
最烂的 `run_dev_tasks`(46→4),但**没有常设闸,它会和别的函数一起再次变胖**,
下次还得靠人工大扫除。需要一个"复杂度不再恶化"的自动拦截。

## What

新增常设复杂度闸,**只拦增量/恶化、豁免存量基线**:

1. **检查脚本** `scripts/check-complexity.py`:用 radon 扫 `orchestrator/`、`plugin/`、
   `scripts/` 的函数圈复杂度,阈值 cc > 15(C 级以上)即候选拦截。
2. **基线豁免**:现状超标函数(扫描时刻)冻结进基线清单 `scripts/complexity-baseline.txt`;
   基线内函数不拦(存量),但**复杂度继续升高**仍拦;基线外**新增**超标函数必拦。
3. **闸语义**:命中(新增超标 或 基线函数恶化)→ 非零退出 + 打印函数清单
   (与 gitguard/check-pool-load 同风格),供合 main 前跑。
4. **radon 常设化**:加入 `requirements.txt`(与 pytest 同级的检查工具,先例成立)。

## 验收标准

| # | 场景 | 期望 |
|---|---|---|
| AC1 | 对当前仓跑 `check-complexity.py` | 返回 0(基线豁免生效,不拦存量) |
| AC2 | 人为新增一个 cc>15 的函数 | 返回非零并点名该函数 |
| AC3 | 基线函数复杂度升高(如某 25→30) | 返回非零并点名(恶化拦截) |
| AC4 | 基线函数复杂度降低(如 46→4) | 放行;且可从基线移除 |
| AC5 | 无 radon 环境时 | 响亮报错(非静默放行),提示 pip install |
| AC6 | 与 check-pool-load 同跑 | 互不干扰,各自独立退出码 |
