# PRD-T-2026-0828-004: 任务分级与快速通道策略

> Phase 1 产物。门禁:templates/gate-checklists/phase1-gate.md
> 来源:用户提出——当前所有工单一刀切走完整 P0–P5 流程,T-001 这类简单任务也跑了半天(部分因平台技术债,但流程本身缺分级)。
> 总原则:**按任务风险与规模分级,低风险任务走快速通道;门禁可减不可省的部分必须写死,分级信息全程可见可审计。**
> 输出形态:本单只交付**策略文档**,评审通过后另行立单改状态机/runner/CLI/Dashboard 实施。

## Why(问题与价值)

当前编排器对所有工单执行同一套 P0–P5 完整流程,无差别对待:

1. **简单任务流程成本倒挂**:文档修订、单点 bug 修复等低风险任务,与跨模块大特性走同样六道阶段、同样多轮审批与产物,流程开销远超任务本身价值(T-001 简单任务跑半天即为实证)。
2. **缺定级入口与标准**:工单创建时无级别字段,也无"谁来定级、按什么定"的规则,导致任何精简诉求都只能靠人工绕过流程,不可控、不可审计。
3. **降级无安全边界**:即使人为"走快点",也没有定义哪些门禁不可省(发布批准、验收命令),一旦放开就有质量失守风险。
4. **与既有保护机制关系不明**:熔断(重试≤3/会诊≤1/判负)在快速通道中如何适用没有约定,可能出现"快速通道任务无限重试"或"熔断误伤快速通道"两种失配。

不做的代价:平台吞吐被低风险任务的大量流程开销拖慢,用户被迫绕开编排器手工操作,流程权威性与台账完整性受损。

## What(范围与边界)

**范围内(策略文档须覆盖的五个议题):**

| 编号 | 议题 | 需求概述 |
|---|---|---|
| R1 | 任务分级标准 | 定义分级维度(改动类型:文档/bug/小特性/大特性;风险;影响面;预估工作量)与级别划分(建议 L1 高/L2 中/L3 低三档,具体档位与判定规则由文档给出),并明确定级权责:建单时人工指定为必填,PM 在 P0 阶段有权升/降级并留痕 |
| R2 | 各级流程映射 | 给出每级对应的流程裁剪表:L1=完整 P0–P5;L2=减化(明确哪些阶段可合并或豁免,如免独立 P2 设计文档、QA 与验收合并);L3/bug=快速通道(明确最短路形态,如 P0 提案+直接开发+验收,乃至人工直接改+事后报备) |
| R3 | 快速通道安全约束 | 写死不可省门禁清单(至少含:发布批准、验收命令执行、台账入账),并定义防滥用机制(级别变更审计、快速通道使用频度上限或告警) |
| R4 | 与熔断/会诊机制兼容 | 明确快速通道下重试/会诊/判负规则是否收紧或保持,超支与失败的处置路径 |
| R5 | 分级信息展示 | 定义工单 YAML 新增级别字段及取值域,以及 Dashboard 上的呈现要求(列表/详情可见级别与定级来源) |

**范围外:**

- 本单**不实施**:不改状态机 TRANSITIONS、不改 runner/CLI/Dashboard 代码;策略评审通过后另行立实施单。
- 不改变各级别内既有阶段产物口径(P0–P5 产物清单以 T-2026-0829-001 为准,快速通道豁免哪些产物由 R2 裁剪表显式列出)。
- 不调整成本台账口径与预算额度(k3 周配额/¥30 日线/¥10 工单帽对所有级别一视同仁)。
- 存量工单不追溯定级,默认视为最高级别走完整流程。

| # | 功能 | 优先级 | 验收标准 |
|---|---|---|---|
| F1 | 分级标准与定级权责定义 | P0 | 见 AC-1 |
| F2 | 各级流程裁剪映射表 | P0 | 见 AC-2 |
| F3 | 快速通道不可省门禁与防滥用约束 | P0 | 见 AC-3 |
| F4 | 熔断/会诊兼容规则 | P0 | 见 AC-4 |

## 非功能需求

- **可判定**:分级标准必须可被人工在 1 分钟内据表判定归属级别,禁止"视情况而定"类不可操作措辞;维度取值须枚举化(如改动类型=文档/bug/小特性/大特性 四值封闭集)。
- **可审计**:定级与任何级别变更必须在工单或台账留痕(谁、何时、从哪级到哪级、理由),快速通道任务的事后记录不得少于完整流程的关键节点(提案、验收结果、发布批准)。
- **不降质**:快速通道豁免的是流程开销而非质量证据;R3 不可省门禁清单在文档中为封闭枚举,任何级别不得豁免清单内条目。
- **兼容**:策略不得要求推翻现有 P0→P5 骨架,只能以"级别→流程模板映射"的方式叠加;存量未分级工单一律按最高级别处理。

## 验收标准

- **AC-1(分级标准)**:文档给出封闭的分级判定表:维度(改动类型/风险/影响面/预估工作量)各自取值域明确,且给出"维度组合→级别"的判定规则,对文档修订、单点 bug、小特性、跨模块大特性四类典型样例各能唯一定级;定级权责写明(建单必填人工指定;PM 可在 P0 升/降级并须留痕)。
- **AC-2(流程映射)**:文档给出"级别→阶段"裁剪表,逐级列明每个 P0–P5 阶段为"保留/合并/豁免"三态之一:L1 全部保留;L2 至少豁免或合并一项且说明理由;L3 给出最短路形态(含人工直接改+报备路径的适用条件与事后报备要素);被豁免阶段的产物缺口逐一列出。
- **AC-3(安全约束)**:文档给出不可省门禁封闭清单,至少包含发布批准、验收命令执行、台账入账三项,并声明任何级别不得豁免;同时给出防滥用规则(级别变更须留痕可审计;快速通道使用频度有上限或告警口径)。
- **AC-4(熔断兼容)**:文档明确快速通道下重试上限、会诊触发、判负/挂起的规则(保持或收紧,取值写死),并说明超 ¥10 工单帽等预算闸对快速通道同样生效。
- **AC-5(展示口径)**:文档定义工单 YAML 级别字段名与取值域,以及 Dashboard 列表/详情页的呈现要求(级别、定级来源、是否走快速通道可见);实施细节留给后续实施单。
- **AC-6(评审通过)**:策略文档经评审通过并落盘于项目约定位置,文中不含"待定/TBD"遗留项(歧义全部登记歧义澄清记录并给出处置结论)。

## 歧义与开放问题

→ 逐条登记到 歧义澄清记录.md

1. 级别档位取名与档数:三档(L1/L2/L3)是否够用,是否需要独立的"hotfix"档与 L3 区分。
2. "预估工作量"维度的量化口径:按预估改动文件数、预估耗时还是预估 token 成本,需定一个可判定的标尺。
3. PM 降级权边界:PM 能否把 L1 直接降到 L3,还是单次最多降一级;升/降级是否需要用户确认。
4. 快速通道频度上限的具体口径:按周配额比例、按绝对次数还是仅告警不阻断,需给出取值。
5. 人工直接改+报备路径中,"报备"的落点(写工单事件?写 ledger?Dashboard 可见?)需在策略中明确。
