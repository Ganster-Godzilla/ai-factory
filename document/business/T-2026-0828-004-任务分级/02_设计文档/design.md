# 设计-T-2026-0828-004: 任务分级与快速通道策略

> Phase 2 产物。对应 PRD:document/business/T-2026-0828-004-prd.md
> 总原则:**本单只交付策略文档,不碰代码;策略以"级别→流程模板映射"叠加于现有 P0–P5 骨架,不推翻;门禁可减不可省的清单写死,分级全程留痕可审计。**

## Why

所有工单一刀切走完整 P0–P5,简单任务流程成本倒挂(T-001 实证);无级别字段、无定级权责、无降级安全边界,与熔断机制关系不明。本设计把 PRD 五个议题(R1–R5)落成一份可评审、可实施的策略文档,全部判定规则封闭枚举化,开放问题逐条给决议,为后续实施单(状态机/runner/CLI/Dashboard)提供唯一依据。

## 策略要点(完整规则以 strategy.md 为准)

### R1 分级标准(AC-1)

四维封闭取值域:

| 维度 | 取值域(封闭) |
|---|---|
| 改动类型 | 文档 / bug / 小特性 / 大特性 |
| 风险 | 低(不触生产路径、可即时回滚)/ 中(触运行路径但回滚容易)/ 高(涉数据、资金、权限、外部接口、公共契约) |
| 影响面 | 单文件或单模块 / 跨模块同项目 / 跨项目或公共契约 |
| 预估工作量 | 小(≤3 文件且 ≤0.5 人日)/ 中(≤10 文件且 ≤2 人日)/ 大(超出中档) |

判定规则(就高原则,逐级过滤):

1. 任一维度命中大特性/高风险/跨项目或公共契约/工作量大 → **L1**;
2. 否则,改动类型∈{文档,bug} 且风险=低 且影响面=单文件或单模块 且工作量=小 → **L3**;
3. 其余 → **L2**。

四类典型样例唯一定级:文档修订→L3;单点 bug→L3(若触高风险路径则升 L2/L1);小特性→L2;跨模块大特性→L1。

定级权责:建单时人工指定 level 为必填;PM 在 P0 阶段可升/降级,单次最多跨一级(L1↔L3 直达不允许),降 L3 须 boss 确认;一切变更记 level_changed 事件。存量工单无 level 字段一律视同 L1。

### R2 流程裁剪映射(AC-2)

三态:保留 / 合并 / 豁免。

| 阶段 | L1 | L2 | L3 |
|---|---|---|---|
| P0 提案 | 保留 | 合并入 P1(提案+PRD 合一文档,一次审批) | 保留(提案=工单 summary+验收命令,一次审批) |
| P1 PRD | 保留 | 合并(同上) | 豁免 |
| P2 设计 | 保留 | 保留(design+tasks 不可免,runner 执行依据) | 豁免(切片=单任务,acceptance_cmd 由建单人随提案给出) |
| P3 开发 | 保留 | 保留 | 保留 |
| P4 验收 | 保留 | 合并(QA 直跑 acceptance_cmd,verdict 记事件,免独立验收报告) | 合并(同 L2) |
| P5 发布 | 保留 | 保留 | 保留(发布批准不可省) |
| 观察窗 | 保留 | 保留(窗口可缩短至 2h) | 豁免(发布批准后即 done,事件记 monitoring_skipped) |

L3 最短路形态:`draft → p0_proposed →(boss 批准)→ p3_queued → p3_running → p4_verifying → p5_ready →(boss 发布批准)→ p5_releasing → done`。

人工直接改+报备(L3-manual)适用条件:改动类型=文档 且风险=低 且不触 `orchestrator/**`;boss 直接修改后 24h 内补建工单直落 done,报备要素=修改文件清单+理由+验收命令执行结果+manual_fix 事件,Dashboard 可见。

豁免产物缺口(L3):PRD/功能清单/歧义记录/设计文档/验收报告/发布记录/观察窗报告——由事件流关键节点(提案审批、verify 留痕、发布批准)替代,事后记录不少于完整流程关键节点。

### R3 快速通道安全约束(AC-3)

不可省门禁封闭清单(任何级别不得豁免):

1. **发布批准**:p5_ready→p5_releasing 必须 boss 审批;
2. **验收命令执行**:acceptance_cmd 必填、实际执行通过、verify 留痕;
3. **台账入账**:成本记账(k3 tokens / deepseek cny)不因级别减免;
4. **状态机迁移**:一切状态推进经 transition() 落事件,禁止直接改 yaml 跳态。

防滥用:级别变更事件留痕(谁/何时/from→to/理由);快速通道频度口径=每周 L3 单 >10 或占当周新建单 >50% 触发告警(Dashboard banner + frequency_alert 事件),不阻断;L3-manual 每周 ≤3 次,超出须 boss 逐单确认。

### R4 熔断与会诊兼容(AC-4)

| 机制 | L1/L2 | L3 |
|---|---|---|
| 重试上限 | ≤3(不变) | ≤2(收紧) |
| 会诊 | ≤1(不变) | 豁免(无架构师产物,达重试上限直接挂起) |
| 判负/挂起 | 现状不变 | suspend(reason_code=circuit_exhausted)转人工,boss 定升级(L3→L1 补流程)或关闭 |

预算闸(¥10 工单帽/¥30 日线/k3 周配额)对所有级别一视同仁,快速通道不豁免。

### R5 工单字段与展示口径(AC-5)

- 工单 YAML 新增 `level: L1|L2|L3`,新单必填(建单指定);缺字段存量单 load 兜底 L1(与 p1_round/created_at 同模式)。级别历史不入 yaml,走事件流(D6)。
- Dashboard:列表页级别徽章(L1/L2/L3 分色)+快速通道标记;详情页显示当前级别、定级来源(建单人/PM 调整)、级别变更历史(事件流回放)、是否走快速通道。
- 实施映射(后续实施单范围,本单不做):TRANSITIONS 加快速通道边、runner 按 level 选流程模板与熔断参数、cli new 加 --level、dashboard 渲染。

## 歧义澄清决议(对应 PRD 开放问题)

1. 档数与 hotfix → 三档够用,不设独立 hotfix 档(D2):急迫性=priority,流程长短=level,正交。
2. 预估工作量标尺 → 预估改动文件数+预估人日双阈(小:≤3 文件且≤0.5 人日;中:≤10 文件且≤2 人日),不用 token 成本(建单时不可知)。
3. PM 降级权边界 → 单次最多升/降一级,禁止 L1↔L3 直达;降 L3 须 boss 确认;全程 level_changed 事件留痕。
4. 频度上限口径 → 告警不阻断:每周 L3>10 单或占当周新建>50% 触发 frequency_alert;L3-manual 每周≤3 次硬上限,超出须 boss 逐单确认。
5. 报备落点 → 事后 24h 内补建工单直落 done,报备要素(文件清单/理由/验收结果)入工单事件 manual_fix,台账照常入账,Dashboard 可见。
