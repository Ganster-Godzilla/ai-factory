# PRD-20260829-001: Dashboard v2 —— 工单中心 / 项目中心泳道图 / 总览可导航化

> Phase 1 产物,源自 PROJ-20260829-001。门禁:templates/gate-checklists/phase1-gate.md

## Why(问题与价值)

Dashboard v1(总览+审批中心)日常使用中暴露三个可用性问题:

1. **工单详情入口深**:详情页存在但全站只有审批中心一处有链接;总览"今日事件摘要"工单号是纯文本,查工单只能手敲 URL。
2. **无全量工单视图**:无法浏览/检索全部工单,找单靠运气。
3. **无跨项目视角**:ai-factory / sk-video-studio / datahub-demo 多项目并行,总览聚合数字(运行中 N)看不出哪个项目卡在哪个阶段。

价值:工单可达性从"背 URL"降为 2 次点击;项目堵塞一眼可见,减少切换上下文追问的成本。

## What(范围与边界)

**做**:
1. 工单中心 `/tickets`:全量列表,项目/状态筛选,关键词搜索(id+summary),排序;行点击进详情。
2. 项目中心 `/projects`:泳道图,行=项目,列=阶段,格内工单 chip 可点进详情;行头项目名点击跳工单中心(带项目筛选)。
3. 总览最小改动:事件摘要工单号链接化;待审批卡片点击跳审批中心;新增各项目状态迷你条。

**不做**(提案已否决,此处重申):
- 不改 Ticket 数据模型/状态机/台账/事件层
- 不做甘特/时间轴;不重做总览首屏;不引 JS 框架/构建链;不做多用户/权限

## 非功能需求

- **部署形态不变**:本地单用户 Flask,绑定 127.0.0.1;新增页面全部 GET 只读,不影响既有 CSRF 防护面。
- **技术栈不变**:Jinja 服务端渲染 + 原生 HTML/CSS,零 JS 依赖(排序/筛选走 GET 表单提交刷新)。
- **性能**:工单池量级(数十~数百单)下,列表页/泳道图单次请求同步扫盘可接受;不做缓存。
- **安全**:沿用 `load_ticket` 的 id 校验;查询参数仅用于过滤/排序,不参与路径拼接。
- **可测性**:views 层保持纯函数装配(不依赖 Flask),新增装配函数纳入 tests/orchestrator/test_dashboard.py。

## 验收标准

1. 导航栏出现"工单中心""项目中心"两项,各页面 active 态正确。
2. `/tickets` 默认按 id 倒序列出全部工单;组合筛选(项目+状态+关键词)+排序结果正确;空结果显示空态文案;每行可点击进 `/ticket/<id>`。
3. `/projects` 泳道图:每个有工单的项目一行;每张工单出现在且只出现在其状态映射的列;chip 点击进详情;项目名点击跳 `/tickets?project=<name>`;无工单时显示空态。
4. 总览:事件摘要工单号为链接;待审批卡片可点击;项目迷你条计数与审批中心/工单中心口径一致。
5. `pytest tests/orchestrator/test_dashboard.py` 全绿(含新增用例)。
