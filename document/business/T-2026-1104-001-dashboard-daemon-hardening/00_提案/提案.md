# 提案:T-2026-1104-001 Dashboard 长驻化根治

## 问题

Dashboard(8321)反复"自动关闭":2026-11-03/11-04 连续实证。
①进程挂在拉起它的会话/终端生命周期上,会话重启即陪葬;
②重启被 PID 锁假阳性挡(OpenProcess 能打开僵尸对象≠活着);
③今晨真凶实锤:事件台账被外部工具写入 UTF-8 BOM,总览页 JSON 解析炸,
异常类型恰好撞上"工单不存在"404 处理器,整页装死成 404(已修 0c4c587)。

## 方向

三件套根治:
1. 脱离会话拉起:计划任务/开机启动项+文档化一键脚本(启动/停止/状态);
2. PID 锁真活判:GetExitCodeProcess 替代裸 OpenProcess;
3. 台账写手侧收口:凡写 *.events.jsonl 的路径统一 utf-8 无 BOM(读端 utf-8-sig 容错已落)。

## 范围

ai-factory 编排器 dashboard 生命周期与台账写入纪律;含回归测试。

## 不做

- 不做 Dashboard 功能面改动(审批中心/总览/泳道不动)
- 不引入 Windows 服务化重型方案(nssm/SCM 另行评估)
- 不动历史事件台账内容(BOM 现场已手术,存量不批量改写)
