# 提案:run_dev_tasks 拆分(复杂度 46→可维护)

- 工单:`pool/tickets/T-2026-0903-002.yaml`
- 类型:refactor / 平台健康(纯重构,行为零变化)
- 溯源:2026-09-03 ruff/radon 代码质量扫描(用户决定一档)

## 问题

`orchestrator/daemon/runner.py:192 run_dev_tasks` 圈复杂度 **46(F 级,全仓最高)**,
97 语句 / 31 分支 / 13 return,把五个职责塞进一个函数:

1. 任务 lazy-load(tasks.yaml 定位+装载,load_failed 挂起)
2. 完工/死锁判定(全 done→p4、无 ready 非全 done→deadlock 挂起)
3. 双成本闸(ds 日现金线 + 单工单预算帽,mingfang 明放降级 budget_warn)
4. 任务派发(worktree/packet/retry_prompt/watchdog 执行 + attempts 计数 + 入账)
5. 验收与判负阶梯(scope 越界检查、acceptance 复检、retry/consult/判负分支)

它是**所有 dev 工单执行的心脏**。复杂度 46 意味着改任何一个分支都可能影响
全部工单——"老出事故"的边角 bug 与这种上帝函数直接相关。

## 方向

纯重构,**对外行为零变化**(同一组输入产生同一组返回值/事件/台账),拆为职责单一的
私有函数,`run_dev_tasks` 退化为清晰的编排入口:

- `_lazy_load_tasks(pool, ticket, project_dir) -> str | None`
- `_completion_or_deadlock(pool, ticket, project_dir) -> str | None`
- `_cost_gate_blocked(pool, ticket, cfg) -> str | None`
- `_dispatch_task(pool, ticket, task, adapter, project_dir, cfg, consult_adapter) -> str`
  (内含 scope/acceptance 验收与 retry/consult/判负阶梯,可再拆 `_verify_task`)

拆分判据:每个函数圈复杂度 ≤ 15(C 级内),`run_dev_tasks` 本体 ≤ 10。
**全套既有测试是行为契约**:重构前后 `pytest tests/` 全绿即行为零变化。

## 范围

仅 `orchestrator/daemon/runner.py` 的 `run_dev_tasks` 及其抽出的私有辅助函数;
不碰任何调用方签名与返回字符串协议。验收标准:

1. 拆分后 `run_dev_tasks` 圈复杂度 ≤ 10,各辅助函数 ≤ 15(radon 实测)。
2. `pytest tests/ -q` 全绿(行为零变化的硬证据)。
3. 返回值字符串协议(`task:*:done`/`retry:`/`consult:`/`suspend:`/`blocked:`/
  `auto: p4_verifying`/`task_failed:`)逐字不变——dev-loop.sh 依赖其解析。
4. ruff F 类零新增。

## 不做

- 不改任何业务逻辑/阈值/事件字段(纯结构调整)。
- 不顺带拆 `main`/`check_gate`/`DshAdapter.run`(复杂度次之,另立单评估)。
- 不改 dev-loop.sh(它消费的返回字符串协议保持不变)。
