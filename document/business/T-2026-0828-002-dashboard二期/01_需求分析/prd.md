# PRD-T-2026-0828-002: Dashboard 新增「项目资产」页(多项目总览)

> Phase 1 产物。门禁:templates/gate-checklists/phase1-gate.md
> 来源:M4 仅有全局总览,受管项目增多后(sk-video-studio、ai-factory 自身、后续更多)需要按项目看资产与进度。
> 总原则:**项目资产页是 per-project 视角,与现有全局总览页并存互补;项目登记信息以 orchestrator.yaml 为唯一数据源。**

## Why(问题与价值)

M4 Dashboard 只有全局总览,所有项目的工单、事件、成本混在一起。当前已登记 3 个项目(orc-e2e、sk-video-studio、ai-factory),后续还会增加。没有 per-project 视角时:

1. 无法回答「sk-video-studio 这个项目现在有几张工单、走到哪一步、花了多少钱」这类最自然的管理问题。
2. 全局数字随项目增多失去可读性,异常(某项目卡单/烧钱)被总量稀释,不易察觉。
3. 项目登记信息(路径、备注)只躺在 yaml 里,操作者要开编辑器才能查到。

不做本功能的代价:多项目运营继续靠人肉翻 yaml + 台账推算,管理成本随项目数线性上升。

## What(范围与边界)

**范围内:**

| 编号 | 需求 | 需求概述 |
|---|---|---|
| R1 | 项目资产导航页 | Dashboard 导航新增「项目资产」入口,页面列出 orchestrator.yaml `projects` 登记的全部项目 |
| R2 | 项目卡片指标 | 每个项目展示:当前活动工单(含所处阶段 P0-P5)、各状态工单计数、今日事件数、成本(DeepSeek 现金 + k3 token,从台账按项目归集)、最近活动时间 |
| R3 | 项目下钻 | 点击项目进入该项目的工单列表页;工单列表中可跳转到既有工单详情页 |
| R4 | 多项目扩展预留 | 项目登记信息(名称/路径/仓库/备注)从 yaml 读取,不硬编码;工单按 `project` 字段过滤;成本按项目归集;新增项目只需改 yaml,不改代码 |
| R5 | 与全局总览兼容 | 现有全局总览页保持可用、数据口径不变;项目资产页与其并存,导航互不冲突 |

**范围外:**
- 不改变工单详情页既有功能与信息架构。
- 不做跨项目对比/排行/图表分析(趋势图等留待后续工单)。
- 不新增成本采集通道;k3/DeepSeek 台账归集口径沿用现有 ledger,不重复造账。
- 不做项目的新增/编辑/删除界面(yaml 是唯一登记入口)。

## 功能清单

| # | 功能 | 优先级 | 验收标准 |
|---|---|---|---|
| F1 | 「项目资产」导航入口与列表页 | P0 | 见 AC-1 |
| F2 | 项目卡片五类指标展示 | P0 | 见 AC-2 |
| F3 | 项目工单列表下钻与详情跳转 | P0 | 见 AC-3 |
| F4 | yaml 驱动的项目登记与过滤归集 | P0 | 见 AC-4 |
| F5 | 全局总览页兼容 | P0 | 见 AC-5 |

## 非功能需求

- **单一数据源**:项目清单、名称、路径、备注以 orchestrator.yaml 为准,Dashboard 不另存副本;yaml 变更刷新页面即生效。
- **口径一致**:项目资产页的成本/事件/工单计数与全局总览页同源同口径,同一时段两页数据可互相印证(各项目之和 = 全局值,误差仅限未归属工单的展示处理)。
- **零归属兜底**:存在 `project` 字段缺失或指向未登记项目的工单/台账记录时,页面不得报错崩溃,归入明确标识的「未归属」区(展示规则见开放问题 3)。
- **性能**:项目数 ≤ 20、工单数 ≤ 500 量级下,页面加载可接受(秒级以内),不做超出此量级的优化。

## 验收标准

- **AC-1(导航与列表)**:Dashboard 导航出现「项目资产」入口;进入后列出 yaml 当前登记的全部项目(不少于 orc-e2e / sk-video-studio / ai-factory 三个),每个项目可见名称与备注信息。
- **AC-2(项目卡片指标)**:对任一项目,卡片同时展示:①当前活动工单列表及每张工单的阶段(P0-P5 标签);②按状态分组的工单计数,计数之和等于该项目工单总数;③今日事件数(与 events 流当日该项目记录数一致);④成本分两项展示——DeepSeek 现金(¥)与 k3 token 数,数值与台账按项目归集结果一致;⑤最近活动时间(等于该项目最近一次事件时间)。无活动项目显示为零值/空态,不报错。
- **AC-3(下钻与跳转)**:点击项目卡片进入该项目工单列表,列表仅含 `project` 字段等于该项目的工单;点击列表中任一工单可打开既有工单详情页且内容正确;可从详情/列表返回项目资产页。
- **AC-4(yaml 驱动扩展)**:在 orchestrator.yaml `projects` 中新增一个登记项(不改任何代码),刷新后项目资产页出现该项目;该项目产生工单与成本后,过滤与归集自动生效。移除登记项后页面相应消失且不报错。
- **AC-5(全局总览兼容)**:现有全局总览页可正常访问,所示全局指标与改造前口径一致;项目资产页各项目指标之和与全局总览对应指标吻合(未归属部分有明确展示)。

## 歧义与开放问题

→ 逐条登记到 歧义澄清记录.md

1. R2「当前活动工单」的状态集合需定义:是否 = 非 closed 的全部状态?closed 工单是否只在计数中出现、不进活动列表?
2. R2 成本归集的时间口径:展示「累计总成本」还是「今日/本周成本」,或两者并存?k3 token 是否同时折算金额展示?
3. `project` 缺失/未登记的工单与台账记录:是单独出「未归属」卡片、还是并入全局总览不出现在项目资产页?(非功能需求已要求不崩溃,具体呈现待确认)
4. 项目登记信息中的「仓库」字段:当前 yaml `projects` 只有 `名称: 路径` 简表,是否本工单扩展 yaml 结构以承载仓库/备注,还是备注先用注释、结构扩展留待后续?
5. 今日事件数的「今日」时区与跨零点口径(本地时区自然日?)需确认。
