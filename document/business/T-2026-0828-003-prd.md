# PRD-T-2026-0828-003: 编排器健壮性八缺口修复

> Phase 1 产物。门禁:templates/gate-checklists/phase1-gate.md
> 来源:SK T-001 冒烟测试 + 用户实测暴露的 8 个健壮性缺口。
> 总原则:**状态推进必须有产物和账的双重证据;验收失败反馈必须含失败子句;成本台账必须覆盖 k3 与 DeepSeek 两侧。**

## Why(问题与价值)

SK T-001 冒烟及用户实测暴露编排器 8 个缺口,均已造成真实损失:

1. **产物验收缺口**:runner 只看角色返回 done 即推进状态,不校验预期产物是否真实落盘。实测 PM 未写 PRD,工单仍推进到 `p1_proposed`。
2. **状态机缺 P1 重做路径**:`p1_proposed` 只能进 P2 或 closed,发现 PRD 不合格只能关单重来。
3. **DeepSeek 成本台账漏记**:实测 DeepSeek 侧 ¥4.81 / 506 次 / 18.36M token,ledger 记 ¥0,导致 ¥30 日线与 ¥10 工单帽对 dsh 完全失效(k3 侧已随 stdin 修复)。
4. **relay 周计数虚高**:周计数把 cache_read 计入,读数虚高 5 倍以上(15.7M vs Kimi 控制台周用量 9%),会诊闸误触发,当前靠 30M 临时提额硬挡。
5. **验收反馈失明**:acceptance exit=1 时不回传失败子句,dev 只能盲猜(A1 连错 5 次)。
6. **验收命令口径脆**:验收用 grep 字面量/禁用词/行数判定,不匹配文档排版变体(A1/A2/A3 三连失败)。
7. **scope 越界无强制**:dev 改了 scope 外的 main.py/svelte 文件,验收环节不查(A2)。
8. **超时偏紧**:环境型任务 1800s 超时偏紧,B1 pip 安装 25 分钟超时致死。

不修的代价:状态机空转(无产物也推进)、预算闸失效(超支无感知)、dev 无效返工(盲猜式修复)、会诊闸误伤(临时提额掩盖真问题)。

## What(范围与边界)

**范围内(8 项缺口全部修复):**

| 编号 | 缺口 | 需求概述 |
|---|---|---|
| R1 | 产物验收 | 状态推进前必须校验本阶段预期产物存在且非空 |
| R2 | P1 重做路径 | `p1_proposed` 支持驳回回 P1 重做,不必关单 |
| R3 | dsh 台账 | DeepSeek 调用的成本/次数/token 记入 ledger,日线与工单帽对其生效 |
| R4 | relay 周计数口径 | 周预算计数剔除 cache_read 虚高,与厂商控制台口径一致 |
| R5 | 验收反馈 | 验收失败必须回传具体失败子句给 dev |
| R6 | 验收口径健壮 | 验收判定容忍文档排版合理变体,不因格式差异误判 |
| R7 | scope 强制 | 验收环节检查改动文件是否越出工单 scope,越界即失败 |
| R8 | 超时分级 | 环境型任务(依赖安装等)超时上限放宽,与常规任务区分 |

**范围外:**
- 不改变现有 P0→P5 主流程骨架与人工审批节点。
- 不新增会诊/预算之外的成本模型;k3 侧 stdin 修复已完成,不在本单。
- 不做 UI 改造。

## 非功能需求

- **双重证据原则**:任何状态推进必须同时满足「预期产物存在」且「本次调用已入账」,缺一不得推进。
- **台账一致性**:ledger 中 k3 与 DeepSeek 两侧记录口径一致(成本/次数/token 三字段齐全),任一侧缺失视为缺陷。
- **口径对齐**:relay 周预算读数与 Kimi 控制台周用量偏差 ≤ 10%;消除后对 30M 临时提额进行回归评估(目标回落至正常额度)。
- **兼容**:既有进行中的工单状态可平滑迁移,不要求关单重开。

## 验收标准

- **AC-1(产物验收)**:构造 PM 角色返回 done 但未写 PRD 的用例,工单**不得**进入 `p1_proposed`,应停在当前态并给出缺产物提示;产物存在且非空时正常推进。
- **AC-2(P1 重做)**:`p1_proposed` 状态下执行驳回操作,工单回到 P1 重做态而非 closed;重做后可再次进入 `p1_proposed`,历史轮次可追。
- **AC-3(dsh 台账)**:触发一次 DeepSeek 调用后,ledger 出现对应记录(成本 > 0、次数 +1、token > 0);模拟 DeepSeek 累计成本超 ¥30 日线或单工单超 ¥10 帽,对应闸门触发阻断。
- **AC-4(周计数口径)**:同一时段 relay 周计数与 Kimi 控制台周用量偏差 ≤ 10%;构造含大量 cache_read 的调用,周计数不因 cache_read 显著膨胀;会诊闸不再因虚高误触发。
- **AC-5(失败子句回传)**:构造验收 exit=1 用例,dev 收到的反馈中**必须包含具体失败子句**(哪条断言/哪项检查失败),不得只有退出码。
- **AC-6(口径健壮)**:对同一合格产物给出排版变体(换行位置、标题层级、空白差异),验收判定结果一致通过;真正缺内容时仍判失败。
- **AC-7(scope 强制)**:构造 dev 改动 scope 外文件的用例,验收判失败并指出越界文件清单;改动全部在 scope 内时不受此检查影响。
- **AC-8(超时分级)**:环境型任务(如 pip 依赖安装)允许超过 1800s 完成而不被判死;常规任务超时行为不变;超时配置可按任务类型区分且有明确上限。
