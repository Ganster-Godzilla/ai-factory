# 技术方案: Dashboard v2 —— 工单中心 / 项目中心泳道图 / 总览可导航化

> Phase 2 产物,依据 document/business/dashboard/01_需求分析/PRD.md。门禁:templates/gate-checklists/phase2-gate.md

## Architecture(结构与边界)

全部改动收敛在 `orchestrator/dashboard/` 展示层 + `tests/orchestrator/test_dashboard.py`,不动 daemon 层(状态机/台账/事件/工单模型):

```
orchestrator/dashboard/
  app.py                    # +2 路由:GET /tickets、GET /projects;导航 active 传递
  views.py                  # +3 纯函数装配:ticket_list / swimlanes / project_strips
  templates/
    base.html               # 导航 +2 项;卡片可点样式
    tickets.html            # 新:筛选表单 + 全量列表
    projects.html           # 新:泳道图(CSS grid)
    index.html              # 改:事件摘要链接化、待审批卡片可点、项目迷你条
```

分层纪律(沿用 v1):views.py 纯函数不 import Flask,输入 `(pool, cfg, query_params)` 输出 dict;app.py 只做请求解析与渲染。

## How(关键实现)

**1. 工单中心 `/tickets`**
- `views.ticket_list(pool, project=None, state=None, q=None, sort="id_desc") -> dict`
- 数据源复用 `_all_tickets(pool)`;过滤链:project 精确等值 → state 精确等值 → q 大小写不敏感子串匹配 `id + summary`
- 排序:`id_desc`(默认,id 含日期+序号即创建序)/ `id_asc` / `mtime_desc`(工单 yaml 文件 mtime,近似最近更新)。`mtime` 需带文件路径,装配函数内部用 `path.stat().st_mtime`,排序后只把 Ticket 交给模板
- 非法 project/state/sort 值:忽略回默认(不 400,本地工具不做严苛校验)
- 筛选项数据源:project 列表 = 全量工单 `distinct project`;state 列表 = `VALID_STATES` 排序
- 模板:顶部 GET 表单(下拉×2 + 搜索框 + 提交),表头"工单号/最近更新"为排序链接(保留其他 query 参数,模板内用 `request.args` 重建)

**2. 项目中心 `/projects` 泳道图**
- `views.swimlanes(pool) -> {"columns": [...], "rows": [{"project": name, "cells": {col_key: [Ticket]}}]}`
- 列定义(固定 8 列,顺序即流水线顺序):
  | 列 key | 标题 | 包含状态 |
  |---|---|---|
  | p0 | P0 提案 | draft(探针草稿)、p0_proposed |
  | p1 | P1 需求 | p1_drafting、p1_proposed |
  | p2 | P2 设计 | p2_designing、p2_approved |
  | p3 | P3 执行 | p3_queued、p3_running |
  | p4 | P4 验证 | p4_verifying |
  | p5 | P5 发布 | p5_ready、p5_releasing |
  | mon | 监控 | monitoring |
  | susp | 挂起 | suspended |
- closed / done 不进泳道图(歧义澄清 #5)
- 行:按 project 分组,行序按项目名字典序;chip = `<a href="/ticket/id">` 显示工单号 + 摘要截断 12 字
- 布局:CSS grid,`grid-template-columns: 120px repeat(8, 1fr)`,首列项目名(链接到 `/tickets?project=X`);表格语义用 div+role 或纯 table 均可,选 table 改造最少(列宽 colgroup)
- 空态:无工单时显示"暂无进行中工单"

**3. 总览改动**
- `views.project_strips(pool) -> list[dict]`:`[{"project", "running", "pending", "suspended"}]`,口径复用 `pending_groups` + `RUNNING_STATES`(pending 排除 suspended 组,与 overview_data 一致)
- index.html:事件摘要 `{{ tid }}` → `<a href="/ticket/{{ tid }}">`;待审批卡片包一层 `<a href="/approvals">`;新增"项目状态"小节渲染 project_strips(每格点击跳 `/tickets?project=X`)
- overview_data 增加 `project_strips` 键(模板参数透传)

**4. 导航**
- base.html:总览 / 工单中心 `/tickets` / 项目中心 `/projects` / 审批中心 `/approvals`;各模板 `{% set active = ... %}`,ticket.html 详情页 active 归 'tickets'(原为 'approvals',详情页现在主要从工单中心进入)

## 数据设计

无新增持久化。派生数据全部运行时计算:

- 工单列表过滤/排序:内存操作,数据量数百单内可忽略成本
- mtime 排序:`path.stat().st_mtime`,工单 yaml 每次 transition 都 save,mtime ≈ 最近活跃时间(歧义澄清 #4)
- 泳道分组:`_all_tickets` 一次扫描,按 (project, 状态→列) 双键归位

## 接口契约

| 路由 | 方法 | 参数 | 响应 |
|---|---|---|---|
| `/tickets` | GET | `project?` `state?` `q?` `sort?`(全部可选) | 200 HTML;非法参数忽略回默认 |
| `/projects` | GET | 无 | 200 HTML |
| 既有路由 | 不变 | — | — |

模板上下文契约:
- `tickets.html`:`tickets, projects, states, cur(project/state/q/sort)`
- `projects.html`:`columns[{key,title}], rows[{project, cells}]`
- `index.html` 增量:`project_strips`
