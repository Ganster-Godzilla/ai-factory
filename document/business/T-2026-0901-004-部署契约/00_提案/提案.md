# T-2026-0901-004 提案:release 契约补"部署"环节(本地/远程双形态)

## 问题

release 契约只到"合 main + tag + 本地收口":push GitHub 靠手工兜底,部署到运行环境
**从来没有环节**。003/004 发布一夜,服务器 47.109.84.154 上 /api/store-profiles、
/api/login 仍 404——发布≠上线,boss 2026-09-01 实锤抓出。

## 方向

p5 发布契约扩"部署+冒烟+回滚"三条款,deploy target 抽象为 local/remote 双形态——
**没有云服务器时 CI/CD 就是本地化**:local 是一等公民(不是 remote 的降级),
remote 是其中一种 target(boss 2026-09-01 核心约束)。部署执行脚本化、
部署后健康检查冒烟、冒烟失败建 incident 不静默放行、回滚可演示。

消化首次部署实战情报五条(sudo 卡点 / uid 穿透 / venv 策略 / .env 差异 / nginx 常识),
  - 补(2026-09-01 部署收官):sudo 最终解=deploy 账户 passwd -S=L 锁定,绕行 ssh -tt + su - root;遗留 root SSH PermitRootLogin yes 隐患——契约收编必须回改(sudoers 单条 NOPASSWD + PermitRootLogin no)。另两条缺陷回修 main:drawtext 字体跨平台(457295f)、验收脚本 admin 凭据钉死(2147dc9),③dist 构建 API base 钉死 127.0.0.1 致外网白屏(633d356 修:默认同源+fetchMe 按未登录);冒烟清单由此加两条硬规:构建时查 VITE_API_BASE_URL 约定 + 部署后必须从非部署机真实浏览器验证(curl 200 验不出白屏),
逐条转化为契约条款或部署单必带项。

## 范围

- release 契约扩条款:deploy 步骤脚本化(tar+ssh 标准路径、前端本地构建 dist、
  后端依赖差异检查)
- 部署后健康检查冒烟:/api/health + 关键新路由 200 + 前端 200,全绿才算发布成功
- 回滚说明:上一版包留存 + systemctl 回切(remote)/ git tag 回切 + 进程重启(local)
- 服务器 .env 管理约定:密钥不落库、.env.example 与服务器 .env 差异清单进部署冒烟
- 双形态各演示一次:local 以 ai-factory 自身为试点,remote 以 sk-video-studio 为试点
- 冒烟失败路径演示:自动建 incident 工单 + 回滚说明可用

## 不做

- 不做通用 CI/CD 平台(GitHub Actions/Jenkins 不引入)
- 不做多环境(dev/staging/prod 分级),单环境先行
- 不动现有 release 的合并/tag 语义
- 不替 boss 决策 deploy 凭证保管方式(sudo 密码/SSH key 权限,列为待决策项)
