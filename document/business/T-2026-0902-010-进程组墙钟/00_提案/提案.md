# 提案:runner 进程组墙钟看门狗(适配器无关)

## 问题

编排器的角色超时帽在 `subprocess.run(timeout=)` 层——**只有父进程(advance 的 python)
活着才生效**。父进程一死(TaskStop/崩溃/会话断开),角色进程(dsh/claude -p)变孤儿,
无人限时,可无限烧下去。实证:T-2026-0901-009 的 release 角色游荡侦查 2 小时
(进程玄学/CPU 采样),无人终止;009-S6 两次超时死掉的 dev 留孤儿回归链在工位跑,
污染并发验收。教训档 #20 已记,机制未补。

## 方向

在 runner 调用适配器处加**进程组级墙钟看门狗**:角色子进程挂进独立进程组
(Windows: Job Object 或 CREATE_NEW_PROCESS_GROUP + 看门狗线程;POSIX: process group),
看门狗持有 pid+截止时刻,父进程死亡不灭火——看门狗到点即按组终止,
并向工单事件流写 `watchdog_killed` 证据。适配器零改动(claude_code/dsh 同一层罩住)。

## 范围

1. runner 角色调用(dev/qa/release/sre/pm/architect 全角色)统一过看门狗包装
2. 墙钟值 = packet.timeout(已有分级:task.timeout/ROLE_TIMEOUT),看门狗只做兜底,
   不改变既有超时语义
3. 终止证据:事件 `watchdog_killed`(pid/墙钟/工单/任务)+ 结果按 timeout 判负
4. pytest:父进程被杀后孤儿按墙钟被收(用短墙钟+sleep 进程实证)

## 不做

- 不做常驻守护进程/系统服务(看门狗随 advance 进程生命周期,尽量轻)
- 不动适配器协议与角色提示词
- 不做跨机器/远程进程管理
- 不改既有 timeout 分级数值
