# T-2026-0903-010 提案:ticket 详情页对裸字符串 tasks 零容忍

## 问题

2026-09-03 发现 T-2026-0903-007/008 详情页 500。根因:交互式执行手工"装 tasks"时把
`tasks: [S1, S2, ...]` 裸字符串列表写进工单 yaml,而 `ticket.html` 按 dict 契约渲染
(`task.get("id")`),Jinja 抛 `'str object' has no attribute 'get'` → 500。
同一份脏数据还会炸 runner 的 `ready_tasks()`(按 dict 取 status/depends_on)。

数据层已当日报修(两单 tasks 重建为 dict + 按事件流回填 status/verify),
但**防御层仍裸奔**:任何会话再手写一次字符串 tasks,详情页/runner 照炸。

## 方向

双层防御,纵深设防:

1. **loader/写入层校验**:`save_ticket` 或装载入口断言 tasks 每项必为 dict 且含 id,
   裸字符串直接拒绝写入(快速失败,把事故挡在写入时)。
2. **展示层容错**(对齐展示层防御规则 R2 None 容错):`ticket.html` 渲染 tasks 时
   兼容 str 项(显示为 id 即字符串本身、其余列 "-"),脏数据不再 500,可看板可诊断。
3. **回归测试**:裸字符串 tasks 工单 → 详情页 200 且页面含字符串 id;
   写入层校验单测:字符串 tasks 写入被拒。

## 范围

- `orchestrator/dashboard/templates/ticket.html` tasks 渲染兼容 str
- tasks 写入/装载校验(点位实现时定:save_ticket 或 transition 装载处,取最小侵入)
- `tests/orchestrator/test_dashboard.py` 回归用例 + 校验单测

## 不做

- 不改历史工单数据(007/008 已修;全池扫描已确认无其他脏单)
- 不改 tasks dict 契约本身(字段不变)
- 不做 runner 对 str tasks 的自动修复/迁移工具(写入层拒入即可)
